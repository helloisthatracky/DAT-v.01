# PreviewKit — `preview_core` v0.2.0

Детерминированная сборка превью моделей для 3ddd.ru по документу «Правила компоновки превью».

**Вход:** 1–2 рендера на белом фоне, опционально сферы материалов и логотип бренда.
**Выход:** комплект JPEG (главное, второе/третье, клоузапы) + `report.json` с 11 проверками.

Библиотека не зависит ни от какого фреймворка: `numpy`, `Pillow`, `PyYAML`. Electron, FastAPI, CLI или граф нод вызывают одни и те же функции.

---

## Быстрый старт

```bash
pip install -e .

# полный комплект из задания
preview build examples/job.example.json -o out/

# без job.json
preview build --views render_a.png render_b.png --model-id 12345 -o out/

# со своей спекой вместо встроенной
preview build examples/job.example.json --spec my-spec.yaml -o out/

# проверить чужое превью, собранное руками
preview validate ready.jpg --role main
```

`--spec` не обязателен: по умолчанию берётся `preview_core/spec.yaml`, который
едет вместе с пакетом. Какая именно спека применилась, CLI печатает первой строкой.

### Если импорт не работает

```bash
python tools/doctor.py
```

Показывает, какую копию `preview_core` реально грузит интерпретатор, совпадает ли
она с той, которую вы редактируете, и есть ли в ней абсолютные внутрипакетные
импорты — с указанием файла и строки. Ничего из пакета не импортирует, поэтому
работает именно тогда, когда импорт сломан.

### Запуск без установки

```bash
python -m preview_core build job.json -o out/       # из корня проекта
python -m preview_core.cli build job.json -o out/   # то же самое
```

Запускать файлы пакета напрямую (`python preview_core/cli.py`) нельзя: у скрипта,
запущенного по пути, нет родительского пакета, и относительные импорты не разрешаются.
Абсолютные импорты это не чинит — при запуске файлом в `sys.path[0]` попадает папка
`preview_core/`, а не корень проекта.

## Ключевые решения

**Матирование не используется.** Оба тестовых файла — RGB без альфы на чистом белом. Композит на белый холст — прямой перенос пикселей, математически точный. Мягкая оценка `α̂ = 1 − min(R,G,B)/255` нужна только для поиска bbox. Это убирает главный риск проекта: вырезание стекла, хрома и полупрозрачных подвесов.

**Композит через darken, а не paste.** На белом холсте `min(canvas, patch)` — побитово точный перенос без ореолов. Побочный эффект: при наложении двух ракурсов белый прямоугольник соседа не затирает содержимое.

**Один масштаб на оба ракурса.** Два вида одной люстры должны быть сопоставимы по размеру. Решатель считает общий `scale` и растягивает объединение до направляющих ровно по одной оси.

**Тень исключается из bbox, но остаётся в кадре.** Контактная тень — светлая, ненасыщенная, мягкая, ниже центра масс. Без отсечки она раздувает bbox и модель перестаёт доходить до направляющих. Валидатор применяет то же правило — иначе он ловил бы выход за направляющие, которого решатель не делал.

**Деградация вместо отказа.** Не влезают два ракурса — падаем до одного с предупреждением. Не влезают сферы — уменьшаем диаметр до `d_min`, потом количество. Каждое понижение попадает в отчёт: оператор должен видеть, что раскладка была тесной.

**Валидатор — отдельный продукт.** `preview validate` проверяет превью, которое эта система не собирала. Тот же код, та же спека.

**Только относительные импорты внутри пакета.** Прямое следствие п. 6.1 техспеки: библиотека вызывается из Electron/FastAPI как внешний пакет и не должна зависеть от текущего рабочего каталога. Правило проверяется статически в `tests/test_imports.py` — рантайм-теста мало, он проходит по случайности, если cwd оказался равен `preview_core/`.

**Спека едет внутри пакета.** `preview_core/spec.yaml`, не корень репозитория. У установленного колеса и у бандла Electron репозитория вокруг нет, а `--spec` должен оставаться необязательным.

## Калибровка

Координаты сняты программно с `121.png` — скриншота PSD-шаблона:

```bash
python tools/calibrate_guides.py assets/121.png
```

```
# calibrated from assets/121.png (1000x1000 artboard)
guides:
  inset_ratio: 0.0265    # 26.5px on this artboard
zones:
  TL: [0.006, 0.003, 0.151, 0.271]
  BR: [0.664, 0.847, 0.994, 0.991]
  # not marked in this template: BL - confirm manually
```

Инструмент отличает направляющую от контура зоны по покрытию: направляющая идёт на всю длину холста, контур зоны — нет.

### ⚠️ Что ещё нужно подтвердить

| Что | Сейчас | Почему важно |
|---|---|---|
| **Inset направляющих** | 2.6% | **Расходится с эталонами.** Скриншот шаблона даёт 2.65%, но 11 непустых эталонов дают медиану 1.56% (диапазон 1.37–2.20%). Ни один эталон не укладывается в 2.6%. Требует решения с арт-директором |
| **Зона BL** | Зеркало BR | В шаблоне не размечена вообще |
| **Логотип 3ddd** | `draw_3ddd_logo: false` | `01-tech-spec.md` говорит «рисуем мы», `overview.txt` — «3ddd сами». Зона резервируется в обоих случаях |
| **Размер холста** | 1500×1500 | Эталоны приходят как 1092×1092; шаблон снят как 1000×1000 |
| **Пороги V/H/S** | 1.25 / 0.80 | Взяты из здравого смысла, не из эталонов. Нужен размеченный датасет |
| **`min_free_area_ratio`** | 0.18 | Условие допустимости клоузапов, в гайде числом не задано |
| **Допустима ли контактная тень** | Да, остаётся в кадре | По новому гайду не проверено |

Всё это живёт в `spec.yaml` и меняется без правки кода.

## Смягчения относительно первой редакции техдокументации

Две проверки понижены по итогам сверки с эталонным набором:

**`tl_zone_clear`.** Модель, растянутая до направляющих, физически всегда задевает верхний левый угол — `003.jpg` из эталонов это подтверждает. Теперь: `fail` только если *мы* поставили туда свой элемент (сферу, логотип); перекрытие моделью больше 60% зоны — `warn`.

**`br_logo`.** Та же логика. Если `draw_3ddd_logo: false`, проверяется, что зона свободна от наших элементов.

Для клоузапов отключены `bg_pure_white`, `guides_touch`, `guides_overflow`, `no_frame` — клоузап по гайду идёт с bleed до края холста.

## Производительность

Комплект из 4 превью (`model.png`, холст 1500×1500) — **~3.8 с** на CPU, без GPU и без сети.

Первая реализация дилатации через `PIL.MaxFilter` давала 17.8 с. Замена на сепарабельную дилатацию через префиксные суммы — ×6. Дилатация на горячем пути: клиренс вокруг модели пересчитывается для каждого превью.

## Детерминизм

Одинаковый вход → побитово одинаковый выход. Проверяется тестом `test_output_is_byte_identical_between_runs`, который сравнивает SHA-256 файлов из двух прогонов. Никаких сидов, сэмплеров и сетевых вызовов в основном тракте.

Рядом с результатом сохраняются `job.json`, версия и хеш `spec.yaml` — старое задание всегда пересобирается по своей версии спеки.
